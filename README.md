# kaumono — 買うものリスト

日用品と食料の在庫台帳。**NFCタグをかざすと、その品目が買うものリストに載る。**

家の消耗品が切れるのは、たいてい手が塞がっている瞬間（風呂場、調理中、詰め替えを
捨てる時）で、そこでメモを取れないから買い忘れる。かざすだけで記録が終われば
その断絶が消える、という一点のための道具。

Flask 1ファイルのサーバと、素の HTML/JS が1枚。依存は Flask だけ。

## できること

- **NFCタグ**: 品目ごとのURLをタグに書いておき、かざすと「欲しい」が立つ。
  Android は既定ブラウザが勝手に開くので実質かざすだけ、iPhone は通知バナーを1タップ
- **タグ用URLは品目側から配る**: 品目を開くと `…/t/<品目ID>` が出るので、コピーして
  NFC Tools 等で書き込む。URLの元は**名前ではなくID**なので、あとで名前を変えても
  貼ったタグは死なない
- **OGPカードの有無**: 品目ごとに持てる。一覧では名前の後に `▤` が付き、付いていない
  ものはカードを作らないと決めたもの。既定は「ある」で、外すのは例外だけ
- **4つの束ね方**: トップを **場所 / 種類 / 店 / 買い方** で切り替えられる。
  「置き場所（どこにあるか）」と「種類（何か）」は直交させてあり、同じ「掃除」でも
  洗剤はトイレ、別のは風呂に置ける。店と買い方は品目のURL・設定から導く
- **買うものは店ごとにまとまる**: 注文はサイト単位で終わるので、Amazon の分・
  楽天の分が分かれていないと片づかない。束ごとに **「全部開く」「全部買った」**。
  楽天・Yahoo! は店ごとに送料条件が違うので、モール名だけでなく店名まで出す
- **購入履歴**: 買った日を積んで、行に「購入 12日前」、品目に「前回◯日前・平均◯日おき」。
  タグを触り忘れても、そろそろだと分かるようにするための保険
- **URLの正規化**: 貼られた短縮リンクや追跡パラメータまみれのURLを
  `https://www.amazon.co.jp/dp/<ASIN>` のような素の形に均す（保存時 + 定期実行）
- ドラッグで並べ替え（場所・種類・品目・見出しごと）、ライト/ダーク、
  編集を捨てる前の確認

在庫の状態は **ある / 欲しい の2値**で、数量は持たない。数えるのは続かないため。

## 動かす

```bash
pip install flask
python3 seed.py          # 叩き台を入れる（空のまま始めてもよい）
python3 server.py        # http://0.0.0.0:8689
```

データは `$KAUMONO_DATA/stock.json`（既定 `~/kaumono-data/stock.json`）。
JSON 1枚なので、中身を見るのも別の場所へ移すのも簡単。

**認証は持たない。** 家庭内 LAN か VPN（Tailscale など）の中に置き、公開範囲は
ネットワーク層で絞る前提。タグに書く URL はシールの表面から誰でも読めるので、
秘密を置く場所ではない。

### 常駐させる

`systemd/kaumono.service` を雛形として使う。`KAUMONO_DATA` と各パスを自分の環境に
書き換えて `/etc/systemd/system/` に置く。

### ホーム画面に追加する

`manifest.json` を持たせてあるので、スマホのブラウザから「ホーム画面に追加」すると
アドレスバーの無い全画面で立ち上がる。アイコンは Lucide の shopping-bag（192/512/
maskable と apple-touch-icon）。端末上部のバーの色はアプリのライト/ダークに追従する。

### URLの正規化を定期実行する

短縮リンク（`amzn.asia` 等）の解決にはネットワークが要るので、保存時ではなく
cron で回す。文字列だけで済む追跡パラメータ落としはサーバが保存時に行う。

```cron
40 4 * * * /usr/bin/python3 /path/to/kaumono/normalize_urls.py
```

## NFCタグ

NTAG215（504バイト）で十分。URLを1本書くだけなので容量は余る。

### 貼るまで

1. アプリで品目を開き、**タグ用URL**をコピーする（`http://<サーバ>:8689/t/itm_xxxxxxxx`）
2. NFC Tools（Android/iOS、無料）で「書き込む → レコードを追加 → URL/URI」に貼り付け
3. タグに書き込み、貼る

**書き込みロック（読み取り専用にする）は押さないこと。** 不可逆で、二度と
書き換えられなくなる。

番号で運用したい場合は、`…/t/07` のような適当な連番を書いておくこともできる。
未登録のタグをかざすと紐付け画面が出るので、その場で品目を選べばよい。
タグを貼ってから中身を決められるのが利点。

### 物理的な制約

- **金属面ではほぼ読めない。** NFCは電磁誘導なので、冷蔵庫のドア・スチール棚・
  アルミ蒸着の詰め替えパウチに直接貼ると反応しない。金属対応シート（フェライト）を
  下に敷くか、金属から離す
- **タグ同士を重ねると読めない。** カードに貼って束ねるような使い方をするなら、
  1枚ずつ位置をずらす（辞書のインデックスと同じ）か、かざす時に束から離す
- **有効距離は約2cm。** 「近づける」ではなく「触れる」つもりの位置に貼る
- **スマホのアンテナは背面の中央〜上部**で、機種によって違う。貼り位置を決める前に
  自分の端末のどこが読めるか確かめる

### 貼る位置

品目ごとに考える必要がある。

- **詰め替えを使うもの**（シャンプー・洗剤）は、ボトルではなく**ストックの最後の1袋**に。
  ボトルに貼ると「詰め替えたばかりで在庫ゼロ」を検知できない
- **買い替えても場所が変わらないもの**は、物ではなく**棚の定位置**に貼る。
  品名を書き添えておくとタグの意味が見た目で分かる
- 全品目に貼る必要はない。**手が塞がっている瞬間に立ち会うもの**だけで足りる。
  残りは一覧から押せばよい

```bash
python -m unittest discover -s tests
```

ネットワークにも実データにも触らない。

## 制限

- **Amazon のカート一括投入は使えない。** `gp/aws/cart/add.html` は GET も POST も
  200 を返すがカートは空のまま（実機確認済み）。個人向けの注文APIは存在せず、
  Dash Replenishment も終了しているので、注文の自動化はできない。
  「全部開く」でタブを並べて人が確定する形が上限
- ブラウザは1回の操作につき1つしかタブを開かせない。「全部開く」は
  ポップアップ許可を出すまで1件しか開かない（塞がれた分は1件ずつ開くリンクが出る）
- **`http://` の生IPで開くと `navigator.clipboard` が無い**（安全なコンテキストでは
  ないため）。コピーは `execCommand` へ落としてあるが、将来ブラウザが
  これも塞いだら HTTPS が要る。カメラを使う機能を足す場合も同様
- 複数人が同時に触ると後勝ち。家庭内の規模を想定している
